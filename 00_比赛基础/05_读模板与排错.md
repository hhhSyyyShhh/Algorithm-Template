# 05 把语法放回算法模板里

## 一、逐项拆读线段树构造函数

`SegTree(const vector<ll>& a):n(a.size()),s(4*n),lazy(4*n){...}`：

1. SegTree 是类名，同名函数是构造函数。
2. const vector<ll>& 是只读引用，避免复制输入数组。
3. 冒号后初始化 n、s、lazy；按类内声明顺序执行。
4. s(4*n)、lazy(4*n) 创建指定数量的 long long，初始为 0。
5. 函数体里 assert(n>0) 检查建树前提，随后 build。

## 二、逐项拆读 Dijkstra 的堆

`priority_queue<pair<ll,int>,vector<pair<ll,int>>,greater<pair<ll,int>>> q;`：

- 元素是 (距离,节点编号)，不是单个整数。
- 第二个模板参数指定底层容器 vector。
- greater 把默认大根堆变成小根堆。
- pair 先比较距离，距离相同再比较节点编号。
- `auto [du,u]=q.top(); q.pop();` 先复制堆顶，再删除。
- `if(du!=d[u])continue;` 跳过旧的距离记录。

## 三、错误现象→检查位置

| 现象 | 优先检查 |
|---|---|
| expected ';' / 类定义后报错 | class/struct 末尾有没有分号 |
| 某函数未声明 | 头文件、命名空间、函数声明顺序 |
| no matching function | 参数类型、const/引用、模板推导、C++版本 |
| cannot bind reference | 是否把临时值绑定到非 const 左值引用 |
| 程序崩溃 / RE | 下标、空队列、悬空地址、递归栈、除零 |
| 结果随机变化 | 未初始化变量、越界、有符号溢出 |
| 循环不结束 | 无符号下标倒序、树状数组下标 0、状态没有推进 |
| 明明用了 long long 仍溢出 | 运算是否先在 int 中完成；上界是否超过 64 位 |
| map 查询后元素变多 | 是否误用 m[key] 进行存在性检查 |
| reserve 后下标赋值崩溃 | reserve 不等于 resize |
| unique 后 size 没变 | 是否忘记 erase(new_end,end) |
| 修改容器后迭代器出问题 | 扩容、erase、rehash 导致失效 |
| Release 下行为变了 | assert 是否有副作用；其他未定义行为是否被优化放大 |
| 多个 main 的链接错误 | 每个模板要单独编译，不是一起链接 |

## 四、编译警告与 Sanitizer【常用】

```bash
clang++ -std=c++17 -Wall -Wextra -pedantic -g   -fsanitize=address,undefined -fno-omit-frame-pointer   "00_比赛基础/示例/03_STL接口.cpp" -o build/stl_check
./build/stl_check
```

先创建 build 目录。AddressSanitizer 可发现许多内存访问错误，UndefinedBehaviorSanitizer 可发现部分未定义行为；它们不是正确性证明，也不保证发现所有错误。先看编译器输出中的第一条错误，后续可能只是连锁反应。

## 五、动手练习（配套示例可作参考）

1. 用 vector 读入整数、排序、去重，并查询某数出现的位置。
2. 用 map 统计字符串词频，观察 find 与 [] 对 size 的不同影响。
3. 设计 Counter 类，提供 add/value/reset，尝试对 const Counter 调用接口。
4. 分别运行正常版与 -DNDEBUG 版断言示例，比较表达式执行次数。
5. 用 priority_queue 实现不断取最小值，解释 greater 的作用。

完成一个练习后，先解释每个变量和接口，再尝试从空文件重写。
